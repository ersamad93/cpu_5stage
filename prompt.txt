Prompt: 5-Stage Pipelined MIPS Core Generation
Objective: Generate a synthesizable Verilog implementation of a 5-stage pipelined CPU core.

1. RTL Architecture Requirements:

Pipeline Stages: Implement five distinct stages: IF (Instruction Fetch), ID (Instruction Decode), EX (Execute), MEM (Memory Access), and WB (Write Back).

Interfaces: * Standard clk and rst inputs.

			* Instruction memory interface (Program Counter Address out, Instruction in).

			* Data memory interface (Address out, Write-Data out, Read-Data in, Write-Enable out).
			

Reset Logic: Ensure all pipeline registers and the Register File (32 entries) are explicitly initialized to zero on a SYNCHRONOUS RESET to prevent X propagation in simulation.
Implement the register file as a 32-element array named exactly `rf` (e.g. `reg [31:0] rf [0:31]`). The tests access `dut.rf[reg]`; any other name will cause failures.

2. Instruction and Data Hazard Handling:

* The test harness supplies the current instruction on the `instr` input each clock cycle (one instruction per cycle). The CPU must use the value on `instr` as the instruction for the current fetch and advance the PC each cycle when not stalled.

* Data hazards: Implement forwarding so that back-to-back dependent instructions produce correct results. In particular:
  - Forward from the EX/MEM stage and from the MEM/WB stage into the EX stage when the instruction in EX needs a operand produced by a previous instruction.
  - Resolve the same-cycle read-after-write case: when the Write Back stage writes a register and the Decode stage reads that same register in the same cycle, the value read in ID must be the value being written in WB (e.g. forward the WB result into the ID stage for rs/rt when mem_wb_reg_write and the destination register equals rs or rt). Without this, sequences like ADD R3,R1,R2 followed by ADD R4,R3,R1 will produce wrong results.

3. Verification:

Run the project's test suite to verify your design before submitting.
